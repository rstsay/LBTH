# 功能脈絡：LBS 虛擬尋寶 PWA

## 目標

依現有產品需求整理功能與工作項目，讓每個垂直切片可獨立追蹤，並能回溯至 PRD 需求及既有 GitHub issue。

## 使用者與功能範圍

- 玩家：以 Email Magic Link 登入、參與已發布遊戲、使用前景 Real GPS 尋寶、查看個人進度與排行榜。
- 管理員：管理多場遊戲與寶藏、檢視營運資料、處理異常覆核、帳號及資料保留作業。
- 系統：以伺服器作為位置驗證、遊戲狀態、搜集、進度及排行榜的唯一權威。

## 文件權責

- 根目錄 `product.md` 是產品需求與驗收標準的唯一權威文件。
- 根目錄 `proposal.md` 記錄已確認方案與系統邊界。
- 本目錄的 `02-prd.md` 是建立此工作區時的 PRD 快照；需求變更時仍須以 `product.md` 為準並同步更新。
- 本目錄 `issues/` 是分組後的垂直切片；根目錄 `issue.md` 提供索引。
- GitHub issue #1–#13 的編號與連結保留；原本未編號的 PWA 延伸工作整理為本地 #14–#18，尚未對應 GitHub issue。

## 固定限制

- 搜集門檻固定 20 公尺，使用標準 Haversine 公式及 6,371,000 公尺地球半徑；GPS accuracy 不得放寬門檻。
- accuracy 大於 50 公尺時不得搜集。
- 玩家只使用前景 Real GPS；Mock GPS 只可用於未發布草稿遊戲的隔離管理員測試。
- 伺服器是位置、狀態、搜集、進度與排行榜的權威來源；不支援離線遊戲或離線搜集佇列。
- Google Maps API Key 由環境變數管理，不得硬編碼或提交至 Git。
- 文件與介面文字使用繁體中文。

## 成功條件

- 每個工作項目有 Feature 分組、PRD 版本、來源需求、相依項及可驗收條件。
- 每個原有 GitHub issue 編號與連結可由新索引找到。
- 產品規格、系統方案及 issue 的權責清楚且不互相覆寫。
