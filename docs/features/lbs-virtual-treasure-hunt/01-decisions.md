# 決策紀錄

## 2026-10-21 — 採用單一產品功能工作區並依垂直切片分組

**Decision:** 建立 `docs/features/lbs-virtual-treasure-hunt/`，以六個 Feature 分組整理 issues；保留既有 #1–#13 編號與 GitHub 連結。原本未編號的 PWA／管理工作區延伸待辦拆成 #14–#18 本地 issue，未建立外部 GitHub issue。  
**Reason:** 現有需求屬於同一個 LBS 尋寶產品，使用單一工作區可避免複製多份互相競爭的產品 PRD。  
**Alternatives considered:** 為每個 Feature 建立獨立 PRD 工作區；會重複產品需求並增加同步負擔。  
**Impact:** 建立本目錄的脈絡、決策、PRD 快照、回饋紀錄、變更紀錄及 issue 分組；根目錄 `issue.md` 改為索引。根目錄 `product.md` 仍是唯一需求權威。  
**Status:** Approved

## 2026-10-27 — 跨裝置 Magic Link 核准與登入交付

**Decision:** 未信任裝置申請登入後留在等待頁；Email 連結直接核准該要求，連結所在裝置不登入。伺服器只把會話交付給持有待登入憑證的原申請裝置，玩家與管理員流程一致。信件連結載入後自動完成核准，不要求再按確認按鈕。郵件掃描器可能先核准連結，申請頁需提供重新寄送方式。
**Reason:** 使用者在裝置 B 開始登入、裝置 A 收信時，A 只負責核准，B 才能繼續進入遊戲或管理模式。
**Impact:** 取代「確認連結在同一瀏覽器登入」及「不同裝置不切換」的舊決策；遊戲回合裝置綁定、單一有效會話與心跳限制維持不變。
**Status:** Approved

## 2026-10-27 — 跨裝置登入等待期限與復原

**Decision:** 待登入核准期限為 3 分鐘；逾時後原登入頁停止輪詢並提示重新登入，舊核准連結無法建立會話。原申請頁遇到暫時網路錯誤時持續重試至期限；核准後如角色工作區載入失敗，重新交換會話並重試。Email 端只顯示「已確認，請查看登入頁面」。
**Reason:** 避免 Android 行動網路短暫中斷造成登入等待永久停止，並清楚結束無人核准的登入要求。
**Impact:** 魔術連結本身仍保留原有效期；登入要求及其核准交付以較短的 3 分鐘期限為準。信件端不再呈現可點擊的第二個確認按鈕。
**Status:** Approved

## 2026-10-27 — 玩家登入裝置鎖與可選裝置信任

**Decision:** 同一玩家只允許一個有效登入會話；新裝置不得取代或撤銷目前會話，只有目前裝置明確登出後才允許其他裝置登入。遊戲回合心跳逾時只暫停該回合，不解除登入鎖。登入頁保留「之後信任此裝置繼續」核取方塊並預設勾選；取消時只建立目前工作階段，不建立長期信任憑證。登入等待頁須明確提示 3 分鐘內確認 Email。
**Reason:** 修正 Android 與 Windows 可同時使用同一玩家帳號的問題，同時避免共用裝置被永久信任。
**Alternatives considered:** 允許遊戲心跳逾時後解除登入鎖，讓其他裝置接手；使用者先前拒絕此替代方案，指定只有登出才允許重新登入。
**Impact:** 更新 `product.md`、工作區 PRD、玩家身份 issue #1、跨裝置會話 issue #2、管理員信任選項 issue #11；修改玩家與管理員 Magic Link 交接及玩家信任裝置登入控制。
**Status:** Approved
## 2026-10-22 — 管理員與玩家的裝置信任登入及暫停 TOTP

**Decision:** 管理員與玩家採相同的逐裝置 Email 確認原則：每台裝置首次使用時完成 Email Magic Link 確認，之後該裝置可免 Email 確認登入。現階段暫停管理員 TOTP 登入要求；保留既有 TOTP 秘密及相關設定，供日後恢復。管理員工作階段仍受既有時效及角色授權控制。
**Reason:** 簡化目前管理員登入，避免 TOTP 設定阻礙管理端使用，同時保留逐裝置 Email 確認。
**Alternatives considered:** 維持每次登入 TOTP 會延續目前登入阻礙；刪除 TOTP 設定會使日後恢復更困難。
**Impact:** 更新 `product.md`、本工作區 PRD、issue #1／#11、管理員 Magic Link 與信任裝置登入流程；伺服器啟動不再要求 TOTP 加密金鑰，未信任的新裝置仍須 Email 確認。
**Status:** Approved

## 2026-10-21 — 管理員進度重置工作流程

**Decision:** 以遊戲篩選參與者，再用匿名代碼查找；不允許 Email 搜尋。顯示完整申請歷程並提供狀態篩選，待確認及可還原項目優先顯示。還原前顯示含匿名代碼、遊戲及原因的確認視窗。補充的管理端查詢不得回傳 Email，並須受管理員授權及稽核。  
**Reason:** 讓管理員正確選擇重置對象並追蹤案件，同時依個資最小化原則降低敏感資料曝光。  
**Alternatives considered:** 以 Email 查找會揭露直接識別資訊；只顯示待辦會失去申請、確認及還原的追溯脈絡。  
**Impact:** 更新本工作區 issue #16；新增受保護的玩家查找與重置歷程查詢，沿用既有雙人確認與還原條件。  
**Status:** Approved

## 2026-10-21 — #14 管理端營運檢視範圍

**Decision:** 管理端按遊戲查詢匿名玩家進度與保留中的搜集事件；營運統計包含各場參與人數、有效搜集總數、完成率，以及全站有效搜集前三名。參與人數按 `game_participants` 計算；完成率以至少有一個啟用寶藏的參與者為分母，完成者須搜集全部啟用寶藏。事件只呈現匿名代碼、寶藏名稱、時間及距離，不含 Email 或精確座標。  
**Reason:** 讓管理員掌握遊戲參與和完成狀況，同時遵循資料最小化及既定事件保留規則。  
**Alternatives considered:** 僅提供整體全站統計無法比較各場狀況；把 Email 或精確位置放入事件清單超出營運查詢所需。  
**Impact:** 更新本工作區 issue #14；需新增受保護且留審計的營運查詢 API 與管理工作區檢視。排行榜沿用 #9 的排序及公開名稱規則。  
**Status:** Approved

## 2026-10-21 — #18 帳號自助刪除與遊戲封存管理範圍

**Decision:** 玩家從個人資料介面自助啟動不可復原的帳號刪除，確認後沿用 `DELETE /auth/me`。不新增管理員代刪、刪除申請清單或帳號復原。管理員可在管理遊戲介面還原 7 天封存期內的遊戲資料，或在草稿階段／封存期屆滿後明確確認永久刪除；還原不恢復遊玩。  
**Reason:** 對齊產品已確認的玩家帳號控制權、不可復原刪除原則及遊戲保留政策。  
**Alternatives considered:** 管理員代刪與刪除申請清單沒有產品流程或權限決策依據，可能擴大帳號操作權限。  
**Impact:** 更新本工作區 issue #18；新增玩家個人資料刪除控制及管理端遊戲封存期限、還原和永久刪除操作，沿用既有 API、保留服務及審計。  
**Status:** Approved

## 2026-10-22 — 玩家信任裝置與 Email 確認返回流程

**Decision:** 玩家每個瀏覽器／裝置首次使用時以 Email Magic Link 確認；之後自動登入。一般登出保留信任，玩家明確忘記裝置或清除瀏覽器資料時撤銷。每次登入仍只允許一個有效遊戲會話；新裝置確認後接續同一場進行中的遊戲、撤銷舊會話並重新取得 GPS。Email 確認在同一瀏覽器完成後通知原頁自動恢復；確認頁在瀏覽器允許時關閉，否則提示返回原頁。  
**Reason:** 避免玩家在已使用的裝置反覆確認 Email，同時保留新裝置驗證與單一有效會話要求。  
**Alternatives considered:** 每次登入均寄信會延續目前的使用阻礙；允許多裝置同時遊玩會改變既有會話規則；依瀏覽器限制無法保證跨裝置或關閉分頁。  
**Impact:** 更新根目錄 `product.md`、本工作區 PRD、玩家身份與跨裝置 issue #1／#2；新增裝置信任憑證、忘記裝置控制、原頁恢復與遊戲接手流程。  
**Status:** Approved
## 2026-10-22 — 玩家遊戲回合裝置綁定與心跳逾時

**Decision:** 裝置信任仍按瀏覽器保存；每個玩家遊戲回合另綁定開始該回合的信任裝置。遊戲頁每 30 秒送獨立心跳，背景頁仍嘗試送心跳但停止定位與位置回報；伺服器每 15 秒檢查。連續 2 分鐘無心跳，僅暫停該玩家回合、保留進度及解除裝置綁定，不改變整場遊戲狀態。玩家主動暫停／退出則立即結束回合。仍有有效心跳時，新裝置不得登入接手；回合暫停後可在新裝置開始新回合。此決策取代同日先前允許新裝置直接接手進行中遊戲的規則。
**Reason:** 防止同一玩家在同一遊戲回合中切換裝置造成並行遊玩，同時讓裝置或系統故障後可在有限時間內恢復。  
**Alternatives considered:** 立即允許跨裝置接手會使仍存活的舊裝置與新裝置產生回合競態；人工管理員解鎖增加營運負擔。  
**Impact:** 更新 product.md、PRD、issue #2、玩家登入／遊戲路由；新增回合裝置雜湊、心跳欄位和伺服器清理週期。  
**Status:** Approved
