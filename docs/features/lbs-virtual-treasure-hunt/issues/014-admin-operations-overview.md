# 管理端玩家進度、搜集事件與營運統計

## User story

身為活動管理員，我希望檢視玩家進度、搜集事件及全站營運統計，以掌握活動狀況。

## 範圍

- 管理員可按遊戲及匿名代碼查找玩家，查看該玩家在該場遊戲的目標數、搜集數、完成狀態及最近 100 筆搜集事件；若還有較舊事件，介面須提示目前僅顯示最近 100 筆。
- 管理員可查看每場遊戲的參與人數、有效搜集總數及完成率。
- 管理員可查看全站有效搜集數前三名，沿用產品排行榜的排序及公開名稱規則。
- 搜集事件僅顯示匿名代碼、寶藏名稱、搜集時間及距離；不得回傳玩家 Email 或精確座標。
- 查詢受管理員權限控管，敏感資料存取須留審計紀錄；回應不得快取。

## 統計口徑

- 參與人數：該場 `game_participants` 的玩家數。
- 有效搜集總數：該場目前有效且保留的搜集紀錄數；已永久刪除遊戲的資料不列入。
- 完成率：至少有一個啟用寶藏的參與玩家中，已搜集該場全部啟用寶藏的人數比例。無參與者或無啟用寶藏時為 0%。
- 搜集事件清單只涵蓋資料保留期限內仍保留的事件，與已保存的排行榜累計分開處理。

## 不包含

- 異常事件判定與雙人覆核由 #10、#15 追蹤。
- 玩家前端進度與排行榜由 #9 追蹤。
- 不提供 Email、精確位置、異常判定或事件匯出。

## 驗收條件

- [x] 管理員可按遊戲及匿名代碼查找玩家，查看該場進度與保留期限內最近 100 筆搜集事件；超過上限時介面有提示。
- [x] 管理員可查看各場參與人數、有效搜集總數、完成率及全站有效搜集前三名。
- [x] 搜集事件及玩家查詢不含 Email 或精確座標；回應標示 `Cache-Control: no-store`。
- [x] 未授權請求遭拒，敏感查詢留有不含玩家識別值的審計紀錄。
