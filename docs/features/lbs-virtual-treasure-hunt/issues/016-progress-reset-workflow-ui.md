# 玩家進度重置申請、雙人確認與還原介面

## User story

身為管理員，我希望提出玩家進度重置、由另一位管理員確認，並在需要時還原，以安全處理進度更正。

## 範圍

- 建立玩家進度重置申請。
- 管理員依遊戲及玩家匿名代碼查找該場參與玩家，不提供 Email 搜尋。
- 顯示完整申請歷程及狀態篩選；待確認與可還原申請優先呈現。
- 要求兩位不同管理員確認。
- 還原前顯示確認視窗，並保留審計紀錄。

## 不包含

- 玩家進度與搜集資料的權威更新由 #7 追蹤。
- 管理員角色、授權與審計機制基礎由 #11 追蹤。

## 驗收條件

- [x] 管理員可依遊戲及匿名代碼查找參與玩家，建立附有原因的重置申請；查詢不回傳 Email。
- [x] 申請歷程可依狀態篩選，並顯示待確認、已完成及已還原紀錄。
- [x] 重置申請須由兩位不同管理員確認後才執行；原申請人不能確認。
- [x] 管理員可在還原確認視窗後依產品規格還原進度；若伺服器判定已有新搜集或已還原，須顯示拒絕結果。
- [x] 申請、確認、執行、查詢與還原均可追溯。

- Key decisions: 新增遊戲參與者匿名代碼查找及重置歷程查詢；待確認申請優先顯示，原申請人不能確認；重置後已有搜集時標示不可還原；還原前以對話視窗確認目標及原因。
- Architectural friction found: 原有後端只有重置申請、確認及還原寫入路由，沒有玩家查找與申請歷程查詢。新增管理員專用 GET 路由，查詢由管理請求中介層稽核；查找回應與稽核摘要皆不含玩家 Email。
