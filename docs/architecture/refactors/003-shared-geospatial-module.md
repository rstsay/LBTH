# Refactor: 前後端共用一份距離實作

**類型：** 架構改善  
**範圍：** `src/geo.ts`、`web/geo.js` 及其匯入點  
**相依：** 無  
**風險：** 低  
**狀態：** 已完成

## 問題

伺服器 `src/geo.ts` 與瀏覽器 `web/geo.js` 分別維護搜集距離常量、地球半徑及 Haversine 公式。現有一致性測試可偵測差異，但程式碼仍重複，修改時可能只更新一端。

## 建議變更

- 保留一份 Node.js 與瀏覽器都可載入的 JavaScript 距離模組。
- 為共用模組提供 TypeScript 宣告，維持伺服器端嚴格型別檢查。
- 前端、伺服器及測試匯入同一份常量與 Haversine 實作。
- 保留距離邊界、跨日期線、高緯度及固定門檻的特徵測試。

## 預期效益

- 單一實作消除前後端公式漂移的可能。
- 共用 20 公尺門檻、6,371,000 公尺地球半徑及未捨入比較。
- 測試直接確認所有呼叫端使用同一實作。

## 防護原則

- 不改變 Haversine 公式、常量、精度或外部 API 行為。
- 不新增建置步驟或 runtime 套件。
- 保留現有搜尋與搜集行為；顯示距離的捨入僅限既有 UI／回應格式。

## 驗收條件

- [x] 前端及伺服器由同一檔案載入距離公式和常量。
- [x] TypeScript 呼叫端保留嚴格型別檢查。
- [x] 測試確認兩端使用同一個函式與相同常量。
- [x] Haversine 距離、20 公尺邊界及現有搜集測試通過。
- [x] 不再有重複距離實作或無關變更。

## 實作紀錄

- 2026-10-26：以 `web/geo.js` 作為 Node.js 與瀏覽器共用的距離實作，新增 `web/geo.d.ts` 提供伺服器 TypeScript 型別宣告；更新伺服器、前端及測試匯入，移除重複的 `src/geo.ts`。
- `tests/frontend-geo.test.js` 新增函式參考相同性檢查；原距離案例與 API 整合測試保留。
- 驗證：距離、搜集與寶藏相關測試 28 項通過，TypeScript 型別檢查通過。
