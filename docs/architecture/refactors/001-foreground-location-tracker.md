# Refactor: 正式前端共用可測試的定位追蹤模組

**類型：** 架構改善  
**範圍：** `src/location.ts`、`web/app.js`、`tests/location.test.ts`  
**相依：** 無  
**風險：** 中  
**狀態：** 已完成

## 問題

`src/location.ts` 提供可注入 Geolocation、頁面可見狀態及時鐘的 `ForegroundLocationTracker`，但正式前端 `web/app.js` 沒有使用它，而是自行管理 `watchPosition`、`clearWatch`、背景切換及位置回報節流。現有定位追蹤測試因此沒有覆蓋正式執行路徑，兩處行為可能逐漸分歧。

## 建議變更

- 建立可由瀏覽器直接載入的定位追蹤模組，並讓 `web/app.js` 使用它。
- 將 Geolocation、頁面可見狀態、時鐘及位置／錯誤回呼維持為可替換的介面。
- 讓測試直接驗證正式前端使用的模組；移除或轉換未被正式程式使用的 `src/location.ts` 實作，避免留下第二套定位行為。
- 保留既有定位生命週期、資料格式與畫面回饋；將 tracker 的位置時間轉成目前 API 所需的格式。

## 預期效益

- 前景／背景切換、停止監看、定位錯誤及回報節流集中在單一模組。
- 測試與正式執行路徑一致，不需真實 GPS 即可驗證定位行為。
- 降低修改定位流程時需同時理解和維護兩份實作的成本。

## 防護原則

- 保留既有外部行為與 API 契約。
- 不在背景取得或回報位置；回到前景後重新取得定位。
- 位置回報最多每 5 秒一次；搜集仍使用最新定位，由伺服器驗證。
- 不改動 accuracy 上限、固定 20 公尺門檻、距離公式或遊戲回合心跳政策。
- 先以特徵測試鎖定現有行為，再進行模組替換。
- 只處理定位追蹤接線，不混入其他前端或伺服器重構。

## 驗收條件

- [x] 正式玩家前端透過單一定位追蹤模組啟動及停止 Geolocation 監看。
- [x] 進入背景時停止位置監看與回報；回到前景時開始新定位監看。
- [x] 位置回報維持每 5 秒最多一次，且搜集使用最新定位。
- [x] 定位錯誤、無效座標、停止及重複啟動等行為有不依賴真實 GPS 的測試。
- [x] 定位回呼格式及玩家可見狀態與目前行為相容。
- [x] 既有定位與搜集測試通過，沒有留下未被正式使用的重複追蹤實作。
