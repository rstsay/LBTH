# Refactor: 將搜集交易流程收斂成服務

**類型：** 架構改善  
**範圍：** `src/games.ts` 搜集路由、搜集交易協調、`tests/collection.test.ts`  
**相依：** 無  
**風險：** 中  
**狀態：** 已完成

## 問題

玩家搜集路由同時處理位置驗證、搜集嘗試紀錄、交易控制、遊戲／玩家／寶藏狀態重查、冪等回應及權威進度更新。HTTP 身分與回應處理和 SQLite 交易協調交錯，使搜集行為難以在 API 之外單獨理解或測試。

## 建議變更

- 抽出專責搜集服務，使用明確的命令輸入及成功／拒絕結果。
- 由服務協調交易、最新遊戲與參與狀態驗證、冪等查詢、距離與 accuracy 判定、搜集紀錄寫入及權威進度更新。
- 路由保留玩家身分、路徑與請求解析，並將服務結果轉換為既有 HTTP 狀態碼及回應格式。
- 以現有搜集 API 整合測試作為行為基線；新增服務層測試覆蓋成功、重試及失敗回滾。

## 預期效益

- 搜集交易與業務決策集中在一個具明確介面的模組。
- 可獨立測試冪等、狀態競態及回滾行為。
- HTTP 路由更容易閱讀，降低其他遊戲路由修改對搜集行為的影響。

## 防護原則

- 保留現有 API 格式、狀態碼、錯誤訊息及成功搜集語意。
- 搜集距離維持固定 20 公尺、Haversine 未捨入值比較；accuracy 大於 50 公尺仍拒絕。
- 搜集事件、該場進度及完成狀態維持原子更新；已存在搜集重試不得重複計分。
- 位置異常及搜集嘗試紀錄保留既有時機與保留行為。
- 不改動資料表、權限、登入、心跳或其他遊戲生命週期流程。
- 保留其他工作目錄變更；不順帶重構整個資料存取層。

## 驗收條件

- [x] 路由不再直接協調搜集交易及進度更新。
- [x] 搜集服務有明確輸入及可由路由映射的結果型別。
- [x] 成功搜集、冪等重試、精度／距離拒絕與進度寫入失敗均有測試。
- [x] 交易失敗時搜集事件不會部分提交。
- [x] 既有搜集 API 回應與定位產品規則保持不變。
- [x] 搜集與相關測試通過，變更未涉及無關遊戲功能。
